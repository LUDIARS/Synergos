## 再開手順

このフォルダは解析時点の保存資料であり、現環境でそのまま実行できる手順ではない。
端末固有の絶対パスはリポジトリ名を起点とした表記に置き換えた。
IP アドレスの例は文書用アドレスへ置き換えており、引用内も同じ処理をしている。
そのため、引用文字列の完全一致検索ではなくファイルと識別子から照合すること。
再利用時は対象リポジトリ、資料、作業先、現在の承認範囲を確認してから設定を移すこと。
以下の実装ワークフローを置いていること自体は、並列委託や反映の実行許可を与えない。
`find-verify.js` は反証結果・重要度判定がそろった項目だけを採用するよう修正した。
保存済みの `findings/` が検証済みに変わったわけではない。

1. `findings/` の残りレンズを `workflows/find-verify.js` で生成し、反証・判定を通す。
2. `workflows/design.js` でテーマごとに統合ブリーフと設計書 2 本 (Synergos / Curare) を生成し、`spec/plan/redesign-<theme>.md` として `design/<theme>` ブランチへコミットする。
3. `workflows/implement.js` で実装可能項目を並列実装し、検証後にテーマブランチへ統合する。
