# ノードの待ち受けアドレス検証

関連タスク: `actio:f71f982b-ee28-41bc-a5ab-9ce5ef67a117`

PR #3422 の追従: `actio:c985c205-740c-4e76-a4f6-3ee6627fc084`。
ローカル main の IPC 試験分離修正を取り込んだ後も、本仕様と検証契約を維持する。

`nodeSettings` は未指定アドレスを表記ではなくアドレスの値として拒否する。
対象は IPv4 の全ゼロ、IPv6 の全ゼロ、その IPv4 写像であり、IPv6 の圧縮・展開・
大文字小文字・スコープ ID による別表記も同じ扱いとする。
有効な具体的アドレス、ポートの扱い、既存のエラー文言は維持する。

## 契約と検証計画

C-1 verifyWildcardRejection(addresses): 未指定アドレスの IPv4・IPv6・IPv4 写像の別表記を既存エラーで拒否する

C-2 verifyValidAddresses(addresses): 有効な IPv4・IPv6・IPv4 写像アドレスと既定ポートを保持する

Augur の計画に従い、既存の `node-config.test.mjs` に再現する回帰テストを追加してから
判定を修正する。実行はこの単体テストだけに限定し、サービスは起動しない。
契約ラッパーはテスト内の検証関数にのみ適用し、本番の設定生成経路には加えない。
